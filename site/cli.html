The dsv command

Validate JSON or JSON-LD files against SHACL shapes from a terminal, a script or CI. The command is installed as dsv, and also as data-standard-validator. 

dsv [options] [documents...]

Install

Requires Node.js 22 or later.

npx @theodi/data-standard-validator -s shape.ttl data.json   # run without installing
npm install -g @theodi/data-standard-validator               # install globally: dsv
npm install -D @theodi/data-standard-validator               # per project: npx dsv

Arguments and options

OptionWhat it does
[documents...]Files or http(s) URLs to validate. With none, or with -, the document is read from stdin. All documents in one command are validated together.
-s, --shapes <source>Required. A SHACL shapes file in Turtle, as a path or URL. Repeat the option to merge several files.
-c, --context <source>A JSON-LD context, as a path or URL. It replaces every document's own @context.
-f, --format <format>text (default), json or markdown.
-o, --output <file>Write the report to a file instead of the terminal.
--no-colorPlain text. Colour is also off when output is not a terminal, or when NO_COLOR is set.
-V, --versionPrint the version.
-h, --helpUsage, examples and exit codes.

Examples

# One file, local shapes
dsv -s person-shape.ttl person.json

# Shapes and context published on the web; every JSON file in a folder
dsv -s https://example.org/shapes/person.ttl -c https://example.org/shapes/context.jsonld data/*.json

# Merge a generated shape with hand-written rules
dsv -s person-shape.ttl -s person-rules.ttl person.jsonld

# Machine-readable output
dsv -s shape.ttl record.jsonld -f json > report.json

# Pipe a document in
curl -s https://example.org/api/person/42 | dsv -s shape.ttl -c context.jsonld

For shapes hosted on GitHub, use the raw.githubusercontent.com address and pin a tag or commit, so that results do not change under you.

How the @context is chosen

  1. If you pass --context, it is used for every document. The report notes whether it was added or replaced the document's own.
  2. Otherwise the document's own @context is used. A URL or a relative path such as "./context.jsonld" is loaded, resolved against the document's location.
  3. With no context at all, the document fails with no-context. Plain JSON read without a context produces no data to check, so calling it valid would mean nothing.

Report formats

text, for people

invalid.jsonld -> fails in Person x status must be one of the permitted values - you gave ex:Retired at status line 5 5 | "status": "ex:Retired", | ^^^^^^^^^^^^ Allowed values: Active, Inactive. 4 problems 1 required field missing, 1 out of range, 1 value not allowed, 1 bad format

json, for programs

The full report object, which is also what the library returns. The structure is stable within a major version and is documented in report-format.md.

dsv -s shape.ttl data.json -f json | jq '.documents[].issues[] | {code, path: .location.jsonPath}'

markdown, for GitHub

A verdict, a table of documents, and every problem with its path, line and fix. It is meant for job summaries, pull request comments and issues.

dsv -s shape.ttl data/*.json -f markdown >> "$GITHUB_STEP_SUMMARY"

Exit codes

CodeMeaning
0Every document conforms.
1Problems were found, including a document that is not valid JSON. Under SHACL's definition, results of any severity mean non-conformance.
2Bad usage: an unknown option, an unknown format, or no --shapes.
3A shapes file, context or document could not be loaded: a missing file, a network or HTTP error, or shapes that are not valid Turtle.

In GitHub Actions

- name: Validate data
  run: |
    npx --yes @theodi/data-standard-validator \
      -s https://example.org/shapes/person.ttl \
      data/*.json -f markdown -o report.md

- name: Show the report
  if: always()
  run: cat report.md >> "$GITHUB_STEP_SUMMARY"

The first step fails the job when the data does not conform. The second publishes the report either way.

Troubleshooting

"This document has no @context, so nothing in it could be checked"

Pass --context, or add an @context to the document.

Everything passes, but you expected failures

Shapes only check what they target. sh:targetClass ex:Person checks nodes with "@type": "Person", and only when your context maps Person to ex:Person. JSON-LD silently drops keys that the context does not define.

Field names appear as IRIs

The context in use has no term for that property. Add one, or supply the context that matches the shapes.

An issue has the code other

The constraint has no plain-English wording yet. Run with -f json to see it under technical, and open an issue.

Every issue code is explained in the error reference.
